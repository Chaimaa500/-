أريد تطوير موقع الشات الحالي الموجود في هذا المشروع ليصبح شات عربي كلاسيكي مستوحى من واجهة Arabian Chat القديمة، مع الحفاظ على الوظائف الحالية وعدم حذف أي وظيفة تعمل. المطلوب تنفيذ التالي: 1. تصميم الواجهة - تحويل الواجهة الحالية من التصميم الأزرق الداكن إلى تصميم Classic Arabic Chat. - واجهة متجاوبة بالكامل مع الهاتف والكمبيوتر. - شريط علوي يحتوي: - الرسائل - الطلبات - الإشعارات - الإبلاغ - الإعدادات - الكبار/الأثرياء حسب نظام الموقع. - شريط سفلي ثابت في الهاتف يحتوي: - الغرف - المتصلين - الأصدقاء - الخيارات - الراديو إن كان موجوداً. - منطقة الرسائل تكون بنفس أسلوب الشات العربي الكلاسيكي: - صورة المستخدم - الاسم - الرتبة - الرسالة - التاريخ/الوقت عند الحاجة. - رسائل النظام تظهر بتصميم مختلف وواضح. - رسائل دخول وخروج المستخدمين تظهر مثل: (# زائر #) (# Admin #) (# Owner #) (# Premium #) 2. قائمة المتصلين عند الضغط على زر المتصلين تظهر قائمة جانبية/نافذة مثل التصميم الكلاسيكي. كل مستخدم يظهر معه: - الصورة - الاسم - علم الدولة - الجنس - حالة الاتصال - الرتبة - الإطار الخاص به. عند الضغط على صورة أو اسم المستخدم افتح ملفه الشخصي. 3. الملف الشخصي صمم Profile Popup قريباً جداً من التصميم الكلاسيكي الموجود في المرجع. يحتوي على: - صورة المستخدم كبيرة. - الاسم. - الرتبة. - حالة الاتصال. - الدولة والجنس. - تاريخ الانضمام. - النبذة/المعلومات الشخصية. - رابط الملف الشخصي. - زر خاص. - زر إضافة صديق. - زر إهداء النقاط إذا كانت الوظيفة موجودة. - تبويبات: معلوماتي الأصدقاء معلومات إهداء النقاط يجب أن يعمل الملف الشخصي بشكل صحيح على الهاتف. 4. الرسائل الخاصة أضف نظام Private Chat بين المستخدمين. عند الضغط على "خاص": - افتح محادثة خاصة مع المستخدم. - الرسائل تحفظ في قاعدة البيانات. - يظهر تاريخ ووقت الرسائل. - يمكن للطرفين إرسال واستقبال الرسائل. - دعم حالة القراءة/عدم القراءة إن أمكن. - دعم الحظر إذا كانت الخاصية موجودة. - لا تعتمد على JavaScript في المتصفح لحماية الخصوصية؛ كل الصلاحيات يجب أن تتحقق من السيرفر/backend. 5. نظام الرتب والصلاحيات ترتيب الرتب من الأقل إلى الأعلى: Member Premium Admin Super Admin Owner Owner أعلى رتبة إدارية. هناك حساب خاص لمالك الموقع، وهو حسابي أنا، ويكون له أعلى صلاحيات النظام. لا تجعل Owner ومالك الموقع نفس الشيء برمجياً إذا كان من الأفضل فصل الصلاحيات: - Owner = أعلى رتبة إدارية للمستخدمين. - Site Owner = حساب مالك الموقع نفسه وصاحب التحكم الكامل بالنظام. 6. صلاحيات Member - استخدام الشات العام. - إرسال الخاص. - مشاهدة الملفات الشخصية العامة. - إضافة أصدقاء. - استخدام المزايا المسموحة له. 7. صلاحيات Premium كل صلاحيات Member مع المزايا الخاصة التي يحددها النظام. 8. صلاحيات Admin - إدارة المستخدمين حسب الصلاحيات الممنوحة له. - حذف/إخفاء الرسائل المخالفة. - كتم المستخدم. - طرد المستخدم. - حظر المستخدم إذا كان مسموحاً له. - إدارة محتوى الغرفة. - مشاهدة سجلات الإدارة التي يسمح له النظام بها. لا يستطيع Admin تعديل Owner أو Super Admin أو Site Owner. 9. صلاحيات Super Admin Super Admin أعلى من Admin وأقل من Owner. يستطيع: - إدارة Admin. - إدارة المستخدمين. - إدارة الغرف. - إدارة الرسائل والمخالفات. - مشاهدة سجلات الإدارة. - تنفيذ الإجراءات التي يسمح بها النظام. لا يستطيع تعديل أو حذف Owner أو Site Owner إلا إذا كان النظام يعطي هذه الصلاحية صراحة. 10. صلاحيات Owner Owner هو أعلى رتبة إدارية. يستطيع: - إدارة Super Admin. - إدارة Admin. - إدارة المستخدمين. - إدارة الغرف. - إدارة الرتب. - إدارة الحظر والكتم والطرد. - مراجعة سجلات الإدارة. - إدارة إعدادات الموقع. 11. Site Owner حساب مالك الموقع يكون له التحكم الكامل: - إدارة جميع الرتب. - إنشاء/حذف/تعديل Admin. - إنشاء/حذف/تعديل Super Admin. - إدارة Owner. - إدارة الغرف. - إدارة المستخدمين. - إدارة إعدادات الموقع. - مراجعة سجلات النظام. - إدارة المحتوى. - إدارة الصلاحيات. لا تضع صلاحيات Site Owner داخل JavaScript فقط. يجب حماية هذه الصلاحيات من backend/database حتى لا يستطيع المستخدم العادي تغيير role من أدوات المتصفح. 12. مراقبة الرسائل الخاصة أضف نظام صلاحيات واضح لمراجعة الخاص عند الحاجة الإدارية/الأمنية. لا تجعل كل Admin يستطيع قراءة الخاص تلقائياً. أنشئ صلاحية مستقلة مثل: VIEW_PRIVATE_MESSAGES ويتم تسجيل كل عملية وصول إلى محادثة خاصة في Audit Log: - من شاهد المحادثة - متى - أي محادثة - سبب/نوع الإجراء إذا كان النظام يدعمه. اعرض للمستخدمين في سياسة الخصوصية/شروط الموقع أن الرسائل الخاصة قد تكون قابلة للمراجعة من الإدارة المخولة لأسباب أمنية أو لمخالفة قوانين الموقع. 13. حذف الرسائل عند حذف رسالة: - تختفي من الواجهة للمستخدمين حسب نوع الحذف. - لا تحذف سجل الإدارة بشكل نهائي. - سجل العملية في Audit Log. - سجل: المستخدم الذي حذف الرسالة الرتبة وقت الحذف الرسالة/معرفها سبب الحذف إن وجد. أنشئ نظام Soft Delete قدر الإمكان بدلاً من الحذف النهائي المباشر. 14. Audit Log أنشئ سجل إداري مركزي. يسجل: - Login - Logout - Delete Message - Ban - Unban - Mute - Kick - Change Role - Change Permissions - View Private Chat - Room Settings Changes - User Account Changes مع: - user ID - admin ID - action - timestamp - target ID - metadata عند الحاجة. لا تسمح للمستخدمين العاديين بتعديل Audit Log. 15. بروفايل مالك الموقع اجعل بروفايل Site Owner مميزاً جداً. يظهر: 👑 صاحب الموقع مع الاسم والصورة والأزرار والمعلومات مثل التصميم الكلاسيكي. أريد إطاراً حصرياً حول صورة مالك الموقع: - جماجم فخمة. - ألوان داكنة/ذهبية. - تأثير دم يقطر من الجماجم. - الدم يكون متحركاً بشكل Loop ناعم. - تأثير بصري واضح وفخم. - لا يكون مجرد Emoji ثابت. - يجب أن يعمل جيداً على الهاتف. - لا يؤثر على سرعة الموقع بشكل كبير. - يفضل استخدام CSS animation أو SVG/Web Animation خفيف بدلاً من فيديو ضخم. هذا الإطار حصري لـ Site Owner ولا يمكن لأي مستخدم آخر اختياره من الواجهة. 16. إطارات الرتب أنشئ نظام Avatar Frames قابل للتوسعة. مثلاً: Member = إطار عادي Premium = إطار Premium Admin = إطار Admin Super Admin = إطار Super Admin Owner = إطار Owner Site Owner = إطار الجماجم والدم المتحرك. لكن تحقق من الصلاحية من backend، وليس من CSS فقط. 17. قائمة الإعدادات عند الضغط على الإعدادات تظهر قائمة كلاسيكية مثل المرجع: - ملف شخصي - قائمة الغرفة - إعدادات الغرفة - إدارة الإجراءات - لوحة التحكم - خروج العناصر التي لا يملك المستخدم صلاحيتها لا تظهر له. 18. لوحة الإدارة أنشئ لوحة تحكم خاصة حسب الصلاحية. Admin يرى فقط ما يسمح له. Super Admin يرى صلاحيات أوسع. Owner يرى كل الإدارة. Site Owner يرى كل شيء. 19. الأمان لا تعتمد على إخفاء الأزرار في frontend كوسيلة حماية. كل عملية حساسة يجب أن تتحقق من: authentication authorization role permission من backend. استخدم IDs آمنة للمستخدمين، وتحقق من ملكية الموارد قبل تعديلها. لا تسمح للمستخدم بتغيير role أو permissions من DevTools. 20. قاعدة البيانات إذا كان المشروع حالياً static GitHub Pages فقط، لا تحاول تنفيذ نظام الحسابات والصلاحيات والخاص بشكل آمن باستخدام HTML/CSS/JS فقط. جهز المشروع ليستخدم Backend وقاعدة بيانات مناسبة، مع API للمستخدمين والرسائل والخاص والرتب والصلاحيات. افصل: Frontend Backend Database Authentication Authorization 21. التصميم اجعل التصميم قريباً من الصور المرجعية التي قدمتها: - Classic Arabic Chat - ألوان أبيض/رمادي/سماوي مع التدرجات الموجودة في النمط الكلاسيكي. - نوافذ Profile Popup. - قائمة المتصلين الجانبية. - شريط رسائل كلاسيكي. - أزرار وقوائم منسدلة. - واجهة RTL عربية بالكامل. لا تنسخ صور أو شعارات محمية بحقوق إذا لم تكن مملوكة للمشروع؛ استخدم عناصر التصميم التي أملكها أو بدائل أصلية. 22. الأداء - Mobile First. - سريع على Android. - الصور مضغوطة. - لا تستخدم animations ثقيلة. - لا تستخدم مكتبات ضخمة بدون حاجة. - حافظ على تجربة سلسة أثناء فتح البروفايل والخاص وقائمة المتصلين. 23. مهم جداً قبل تعديل المشروع: - افحص الملفات الحالية. - افهم البنية الحالية. - لا تحذف الوظائف الموجودة. - لا تستبدل المشروع بالكامل بدون سبب. - نفذ التعديلات بشكل تدريجي. - إذا كان هناك Backend موجود، استخدمه بدلاً من إنشاء Backend ثاني. - إذا كانت هناك قاعدة بيانات موجودة، حافظ على البيانات الحالية. - اذكر لي الملفات التي ستعدلها قبل إجراء تغييرات كبيرة. في النهاية أريد موقعاً يعمل كـ Classic Arabic Chat حقيقي: غرف + متصلين + ملفات شخصية + خاص + أصدقاء + رتب + Admin + Super Admin + Owner + Site Owner + نظام صلاحيات + Audit Log + إدارة الرسائل، مع تصميم الهاتف مطابق قدر الإمكان لستايل الشات العربي الكلاسيكي.
